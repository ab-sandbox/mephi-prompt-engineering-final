# Валидатор пароля — требования v2

## 1. Назначение

Консольное приложение на Java 17 проверяет пароль на соответствие установленным правилам.

Программа предназначена для учебного использования и демонстрирует проверку входных данных с предсказуемым выводом
ошибок.

| Параметр | Описание                                  |
|----------|-------------------------------------------|
| Вход     | Одна строка из стандартного ввода         |
| Выход    | `OK` либо один или несколько кодов ошибок |

## 2. Границы задачи

**Входит в область реализации:**

- Проверка пароля по заданным правилам
- Вывод всех обнаруженных ошибок
- Фиксированный порядок сообщений об ошибках
- Обработка пустой строки и EOF

**Не входит в область реализации:**

- Хранение паролей и аутентификация
- Генерация паролей
- Интерактивные приглашения
- Графический интерфейс, база данных, сеть
- Внешние библиотеки

## 3. Функциональные требования

**R01.** Программа считывает одну строку из стандартного ввода. Разделитель строк не включается в пароль. Пробелы,
табуляции и другие символы внутри строки сохраняются без изменений. Если до получения строки наступает EOF, пароль
считается пустой строкой. Последующие строки игнорируются.

**R02.** Длина пароля должна составлять от 8 до 16 символов включительно. Длина определяется методом `String.length()` в
единицах UTF-16.

**R03.** Пароль должен содержать хотя бы одну заглавную латинскую букву (`A-Z`).

**R04.** Пароль должен содержать хотя бы одну цифру (`0-9`).

**R05.** Допускаются только латинские буквы (`A-Z`, `a-z`) и цифры (`0-9`).

**R06.** Если все правила соблюдены, программа выводит `OK` с переводом строки.

**R07.** При нарушении требования к длине выводится код `LEN`.

**R08.** При отсутствии заглавной латинской буквы выводится код `UPPER`.

**R09.** При отсутствии цифры выводится код `DIGIT`.

**R10.** При наличии хотя бы одного недопустимого символа выводится код `CHAR`.

**R11.** При нескольких нарушениях выводятся все соответствующие коды, по одному на строку, строго в порядке `LEN`,
`UPPER`, `DIGIT`, `CHAR`. Если есть ошибки, `OK` не выводится.

## 4. Технические ограничения

- **Язык:** Java 17
- **Библиотеки:** только стандартная библиотека Java
- **Тип приложения:** консольное
- **Объём:** от 50 до 150 непустых строк Java-кода без учёта комментариев
- **Зависимости:** внешние библиотеки не используются
- **Ограничения:** без GUI, базы данных и сетевого взаимодействия
- **Тестовые данные:** только вымышленные пароли

## 5. Критерии завершения

**C01.** Программа компилируется и запускается на Java 17.

**C02.** Все требования R01–R11 проверены тестами с сохранением фактических результатов.

**C03.** Выполнено не менее 8 различных сценариев на финальной версии, включая минимум 3 граничных.

**C04.** Сохранены команды запуска, результаты проверок и подтверждающие материалы.

**C05.** Объём Java-кода составляет 50–150 строк по установленным правилам подсчёта.

**C06.** Сохранены карта процесса, промпты, независимый аудит, журнал и пакет передачи.

**C07.** Задокументирован дефект, определена область его влияния, выполнено исправление и повторные проверки с
сохранением результатов.

**C08.** На финальной версии выполнена полная регрессионная проверка.

**C09.** Подготовлены матрица прослеживаемости и решение о приёмке.

**C10.** Подготовлены итоговый отчёт и ZIP-архив со всеми обязательными материалами.
