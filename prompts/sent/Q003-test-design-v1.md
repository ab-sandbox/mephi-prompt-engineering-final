# Q003 — Проектирование проверок

## Цель

Подготовить тестовые сценарии для валидатора пароля до реализации программы.

## Входные данные

- `requirements-v2.md` — актуальные утверждённые требования.
- `Q002-requirements-analysis-response.md` — результат анализа требований.

Приоритет имеют утверждённые требования v2.

## Задача

Сформировать минимально достаточный набор тестовых сценариев, покрывающий все требования R01–R11.

## Ограничения

- Не изменять требования.
- Не генерировать Java-код.
- Использовать только вымышленные пароли.
- Не менее 8 различных сценариев.
- Не менее 3 граничных случаев.

## Формат ответа

Markdown-таблица со столбцами:

- ID сценария (T01, T02 и далее).
- Описание.
- Входные данные.
- Ожидаемый вывод.
- Проверяемые требования.
- Граничный случай (да/нет).

Пустую строку, EOF, пробельные символы и переводы строк обозначать явно. Ожидаемый вывод записывать с сохранением
порядка строк.

## Критерии успешности

Все требования R01–R11 покрыты. Ожидаемые результаты однозначны и соответствуют требованиям v2.

## Работа с неопределённостью

При невозможности однозначно определить ожидаемый результат указать причину. Не изменять требования и не придумывать
отсутствующие правила.
